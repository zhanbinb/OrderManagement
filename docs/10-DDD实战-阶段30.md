## 一、分层结构与依赖方向

```
OrderManagement.Api           ← 组合根：DI 注册、Controller、中间件
  └→ OrderManagement.Application   ← 用例编排（OrderApplicationService）
       └→ OrderManagement.Domain        ← 纯业务：聚合根/值对象/领域异常/仓储接口（无任何外部依赖！）
  ← OrderManagement.Infrastructure     ← 实现 Domain 的接口（EF Core 映射、Repository）
```

- **依赖规则**：Api → Application → Domain ← Infrastructure（依赖只指向内层）
- Domain **不依赖 EF Core** —— 换数据库只动 Infrastructure
- 命令：`dotnet new classlib -f net10.0` → `dotnet sln add` → `dotnet add <proj> reference <proj>`

## 二、Domain 层设计

### 1. 值对象 Money（record）

```csharp
public record Money(decimal Amount, string Currency)
{
    public Money Add(Money other) { if (Currency != other.Currency) throw ...; return new Money(Amount + other.Amount, Currency); }
    public Money Multiply(int quantity) { ... return new Money(Amount * quantity, Currency); }
}
```

- **record 值相等**（`a == b` 比字段）、不可变、方法返回新对象

### 2. 聚合根 Order

```csharp
public class Order
{
    private readonly List<OrderItem> _items = [];                    // 封装集合，外部拿不到可变引用
    public long Id { get; private set; }
    public OrderStatus Status { get; private set; }
    public IReadOnlyCollection<OrderItem> Items => _items.AsReadOnly();
    public Money TotalAmount => /* 遍历 _items 汇总 */;

    public void AddItem(...) { EnsurePending(); _items.Add(new OrderItem(...)); }
    public void Pay() { EnsurePending(); if (_items.Count == 0) throw new BusinessException(...); Status = OrderStatus.Paid; }
    public void Cancel() { ... }
    private void EnsurePending() => /* 非 Pending 抛业务异常 */;
}
```

**要点**：
- **所有状态变更走聚合根方法**（`EnsurePending()` 守卫），不允许外部直接改 Status
- `private set` + 私有构造保护不变性；EF Core 物化用 public 无参构造（`private Order(){}` 与 `public Order(){}` 并存会 **CS0111**）
- 子实体 `OrderItem` 构造与 `UpdateQuantity` 用 `internal`（同程序集可见）
- **聚合 = 事务边界**：一次 `SaveChangesAsync()` 默认事务；跨聚合用领域事件 + Saga + Outbox，**禁止大事务包住 HTTP/MQ**

### 3. 领域异常与 HTTP 映射

```csharp
// GlobalExceptionHandler : IExceptionHandler（switch 映射）

KeyNotFoundException => 404 NotFound
ArgumentException    => 400 BadRequest

```

### 4. 领域事件（进程内最小实现）

```csharp
// Order.Pay() 内：_domainEvents.Add(new OrderPaidEvent(Id, DateTime.UtcNow));
// 分发顺序：SaveChanges → Dispatch（IServiceProvider 解析 IDomainEventHandler<T>）→ ClearDomainEvents()
```

- **领域事件（进程内）vs 集成事件（RabbitMQ）**：进程内分发会丢消息，要可靠必须 **Outbox**
- **Domain 无外部依赖 → 最适合 xUnit 单元测试**（本项目 6 个领域单测不启 API、不连库）

## 三、Infrastructure 层（EF Core 映射）

```csharp
public class OrderConfiguration : IEntityTypeConfiguration<Order>
{
    public void Configure(EntityTypeBuilder<Order> builder)
    {
        builder.ToTable("Orders");
        builder.Ignore(x => x.TotalAmount);                    // 计算属性不落库
        builder.OwnsMany(x => x.Items, item =>                 // 明细是聚合一部分 → OwnsMany
        {
            item.ToTable("OrderItems");
            item.WithOwner().HasForeignKey("OrderId");         // 级联删除
            item.HasKey(x => x.Id);
            item.Property(x => x.Id).ValueGeneratedNever();
            item.OwnsOne(x => x.UnitPrice, money =>            // Money 值对象展开成两列
            {
                money.Property(x => x.Amount).HasColumnName("UnitPrice").HasPrecision(18, 2);
                money.Property(x => x.Currency).HasColumnName("Currency").HasMaxLength(3);
            });
        });
    }
}
// Program.cs：AddDbContext<OrderManagementDbContext>(o => o.UseNpgsql(GetConnectionString("DddConnection")))
//             builder.ModelBuilder.ApplyConfigurationsFromAssembly(...) 或 DbContext 内 ApplyConfigurationsFromAssembly
```

**Migration**（独立库 `OrderManagementDddDb`，连接串键 `DddConnection`，避免与旧 Orders 表冲突）：

## 四、Repository（仓储）与查询策略

```csharp
// Domain 定义接口（无 EF 依赖）
public interface IOrderRepository {
    Task<Order?> GetByIdAsync(long orderId, CancellationToken ct = default);
    Task AddAsync(Order order, CancellationToken ct = default);
    Task SaveChangesAsync(CancellationToken ct = default);     // 事务提交点
}
// Infrastructure 实现
public async Task<Order?> GetByIdAsync(long id, ct)
    => await _dbContext.Orders.Include(x => x.Items).FirstOrDefaultAsync(x => x.Id == id, ct);
```

**查询策略三原则**（回答「改一个明细为何要加载整个聚合」）：

| 场景 | 做法 |
| --- | --- |
| 完整聚合操作（改明细/支付） | `Include` 加载全聚合（聚合是不变性边界） |
| 只读列表/详情展示 | **`Select` 投影下推到 SQL**，不加载聚合 |
| 纯字段条件更新 | `ExecuteUpdateAsync`（绕过 ChangeTracker 与领域行为，慎用） |

- `GetByIdWithoutItemsAsync`（不 Include）时，未加载的 Items **不会被 `SaveChangesAsync()` 误删**
- 1000 条明细的聚合确实重 —— 这是**聚合设计问题**，应按不变性边界拆聚合，而不是跨聚合查一半

## 五、应用层 Application

```csharp
public class OrderApplicationService
{
    public async Task<long> CreateOrderAsync(CreateOrderRequest request, CancellationToken ct = default)
    {
        var order = new Order();
        foreach (var item in request.Items)
            order.AddItem(item.ProductId, item.ProductName, new Money(item.UnitPrice, item.Currency), item.Quantity);
        await _orderRepository.AddAsync(order, ct);      // 只 Add 不立即 INSERT
        await _orderRepository.SaveChangesAsync(ct);     // 真正提交（事务边界）
        return order.Id;
    }
    // GetOrderDetailAsync：只读 → Select 投影返回 OrderDetailResponse
}
```

**DI 排错案例**：`Unable to resolve service for type IOrderRepository while attempting to activate OrderApplicationService` —— 组合根忘了 `AddScoped<IOrderRepository, OrderRepository>()` + `AddScoped<OrderApplicationService>()`。

## 八、面试速记卡

- 「DDD 分层依赖方向？」→ Api→App→Domain←Infra；Domain 零外部依赖
- 「值对象和实体区别？」→ record 值相等/不可变 vs 标识相等；Money 展开两列
- 「为什么改明细要加载整个聚合？」→ 聚合是不变性与事务边界；只读场景应 Select 投影，聚合太大是设计问题要拆
- 「聚合根怎么保护不变性？」→ 私有 set + 领域方法守卫（EnsurePending）+ 集合只读暴露
- 「领域事件和集成事件？」→ 进程内 vs MQ；可靠投递都要 Outbox
- 「EF Core 怎么映射值对象？」→ OwnsOne/OwnsMany 展开列 + Ignore 计算属性
