## 第一批摘要（对话 1~5，详见初版整理）

### 1~2 · 主线开篇（Step 01~04）与 Options 深讲

- **选型**：.NET 10 LTS（2028-11 前支持）优于 .NET 9 STS；Rider 2025.3+ 支持 C# 14
- **Step 03 DI 实测**：Transient 每次解析新实例、Scoped 同请求共享、Singleton 全局唯一；同 ServiceType 多次注册返回最后一个；Captive Dependency 陷阱；「Transient 是每次**解析**创建实例」
- **Step 04 Options 两轮讲透**：配置优先级、三接口生命周期、内部机制（`IOptionsFactory`/`IOptionsMonitorCache`）、Named Options、`ValidateOnStart`、热更新陷阱（构造函数存 `CurrentValue` 不会更新）、实验预期 `options:50, snapshot:100, monitor:100`
- 对话 2 收尾产出《上下文交接提示词》文档

### 3 · Options 综合实验（112 条，主线核心）

- **Migration 排错**：`Failed executing DbCommand ... __EFMigrationsHistory` 是建历史表的正常流程；**migration 比较模型 vs ModelSnapshot 而非数据库**；scaffold `--force` 混用导致空 Up/Down；`string.Empty` vs `null!`；`-infinity` 是 Npgsql 对 `DateTime.MinValue` 的映射
- **事务**：`BeginTransactionAsync/Commit/Rollback` vs `SaveChangesAsync` 隐式事务
- **查询优化链**：ChangeTracker → FindAsync vs FirstOrDefault → AsNoTracking → Select 投影 → 索引最左前缀 → Offset vs Keyset 分页 → ToQueryString → EXPLAIN ANALYZE
- **排错**：`UseExceptionHandler` 需配 `AddProblemDetails`；日志是 MEL 不是 log4net；`dotnet-counters` PATH 问题

### 4 · JWT 认证授权（Step 17.4~17.9）

- **DI 排错**：`Configure<JwtSettings>()` 注册的是 `IOptions<JwtSettings>`，注入要 `.Value`
- 中间件顺序 `UseAuthentication` → `UseAuthorization`；401 vs 403
- Swagger Auth 三方案（本项目用内置 OpenAPI Transformer，Scalar 代码最少）
- 授权语义：`Roles="A,B"` 是 OR，多个 `[Authorize]` 是 AND；Policy 组合；必须显式 `AddAuthorization`；Token 要含 permission Claim

### 5 · Step 18 缓存开篇

- `Add*` 注册服务、`Use*` 执行中间件
- 三缓存对比：`IMemoryCache` / `IDistributedCache` / Redis
- Cache-Aside 流程；`GetOrCreateAsync` + 2 分钟过期 + `AsNoTracking` 替代 `FindAsync`；Serilog 区分 Miss/Hit

## 第二批摘要（对话 6~13，Step 19~24）

### 6 · 健康检查 / 多环境配置 / 安全加固 / Dockerfile（对话 6）

- **Liveness vs Readiness**：`/health/live` 只查进程、`/health/ready` 查 PG+Redis；DB 挂了 live 仍 200、ready 503（K8s Probe 依据）
- **配置加载优先级**：appsettings.json → appsettings.{Env}.json → User Secrets（仅 Development）→ 环境变量 → 命令行；`Jwt__SecretKey` 双下划线映射 `:`
- **环境切换**：`ASPNETCORE_ENVIRONMENT` / `DOTNET_ENVIRONMENT`（更高优先级）/ launchSettings Profile / Rider Run Config；未指定默认 **Production**；`--no-launch-profile` 排除干扰
- **`.env`**：.NET 默认不读（需 DotNetEnv 包且 `Env.Load()` 在 CreateBuilder 前）；Compose 的 `.env` 只做 YAML 变量替换
- **部署对比**：本地 launchSettings+User Secrets / EC2 systemd EnvironmentFile / Docker Compose environment —— 编译一次、多环境注入
- **安全加固 Review**：HSTS 非 Dev 启用（初版写反）、Swagger 仅 Dev、CORS 禁 `AllowAnyOrigin`、JWT Payload 是 Base64Url 非加密、异常只回通用错误+traceId
- **Dockerfile**：多阶段构建、先 COPY csproj 再 restore 吃缓存层
- 结尾：容器启动报 `JWT 配置缺失`（User Secrets 进不了容器）

### 7 · 容器网络 / 数据卷 / Compose 迁移（对话 7）

- **网络**：容器内 `localhost` 是自己，须用 `order-postgres:5432`；服务名即主机名
- **环境变量不可热改**：重建容器注入 `ConnectionStrings__DefaultConnection='Host=order-postgres;...'`
- **数据卷诊断**：`docker inspect --format '{{range .Mounts}}...'` + `SHOW data_directory` 实证数据在匿名卷；Compose `external: true` 复用
- **迁移安全**：先 `pg_dump` 备份 → stop/rm（**严禁 down -v**）→ `up -d --build`
- 两个典型错误：build context 与 Dockerfile 不同目录（`context: ./src/OrderManagement.Api`）；`container_name` 冲突先删旧容器
- Compose 要点：`healthcheck` + `depends_on.condition: service_healthy`、`.env` 插值、`docker compose config -q` 预检

### 8 · Compose 收尾 + 测试起步（对话 8）

- 容器名冲突处理（`docker stop/rm`）；**严禁 `docker compose down -v`** 删 Volume
- 镜像 Tag 版本管理与回滚（`order-management-api:1.0/1.1`）
- 单测三件套：Arrange/Act/Assert、Moq（Setup/Callback/Verify/Times.Once）、`NullLogger<T>`
- InMemory 测试：`UseInMemoryDatabase(Guid.NewGuid().ToString())` 隔离
- **依赖倒置重构**：`OrderService` 改依赖 `IOrderRepository`（Service 可 Mock 的前提）
- CI 初版：setup-dotnet 10.0.x → restore → build

### 9 · 集成测试排错（对话 9）

- **`JWT 配置缺失`**：`UseEnvironment("Testing")` 不加载 User Secrets → 最终用 `builder.UseSetting("Jwt:Issuer", ...)` 注入生效
- **`public partial class Program { }`**：暴露顶级语句 Program 给 `WebApplicationFactory<Program>`
- **EF Core 双 Provider 冲突**（Npgsql + InMemory 同时注册 → 500 而非 404）：必须 `RemoveAll<IDbContextOptionsConfiguration<ApplicationDbContext>>()` 移除残留 `UseNpgsql()` —— 关键修复
- `ConfigureTestServices` + `RemoveAll` 替换依赖（`IDistributedCache` → `AddDistributedMemoryCache()`）
- 固定 `_databaseName` 让同 Factory 各 Scope 共享测试库

### 10 · 集成测试补全 + 限流 429（对话 10）

- 测试从 5 个扩到 10 个：**404 / 201 / 400 / 401 / 403 / 200** 状态码矩阵
- `[ApiController]` 自动模型验证 → 400 带 `errors`，无需 `ModelState.IsValid`
- **401 vs 403 测试细节**：`/api/orders` 列表接口无 `[Authorize]` 所以原先得 200；401 测 `/secure`、403 用 `GenerateTestToken("User")` 测 `/admin`
- **429 排障**：TestServer 所有请求同一 IP 撞限流 → `IsEnvironment("Testing") ? 1000 : 5` 放宽（不删限流，只放宽测试额度）
- CI workflow 最终形态：restore → build(Release) → `dotnet test --no-build`

### 11 · Pkcs 漏洞排查 + 工具选型（对话 11）

- `dotnet list package --vulnerable --include-transitive` + `dotnet nuget why` 定位传递链：`EF Core Design` / `Microsoft.Data.SqlClient` → `Pkcs 9.0.11`（高危 GHSA-846f-f764-76mx，修复版 9.0.21 / 10.0.13）
- 修复策略：统一 EF Core Design 到 10.0.14 + 显式引用 `Pkcs 10.0.14` 覆盖传递解析
- **NU1301 网络排错**：`198.18.0.0/15` Fake-IP → 终端流量没走代理致 TLS 失败；诊断 `scutil --proxy`、`dig`、`dotnet nuget locals all --clear`；不关签名验证
- 工具五层选型：Rider/Roslyn（日常）+ CodeQL（PR 门禁）+ NuGet 漏洞扫描 + xUnit + Actions；问题分级（严重必修、中评估、低可忽略）
- `dotnet format --verify-no-changes` 做格式门禁

### 12 · CodeQL + 缓存一致性 + Outbox（对话 12）

- **CodeQL Default setup**：独立于 CI，push 默认分支/相关 PR/定期触发；建议设 PR Required Status Check
- **`cs/log-forging`（CWE-117）**：用户输入换行符可伪造日志行 → 转义修复（`LogSanitizer.Sanitize()`）而非删日志
- Roslyn 配置：`EnableNETAnalyzers` + `AnalysisLevel=latest` + `AnalysisMode=Recommended`；CA1848/CA2201/CS8981/NU1903 分级
- **缓存一致性三档**：Cache-Aside+TTL（普通）/ +MQ 重试（中大型）/ Outbox+MQ+幂等（核心业务）；TTL 兜底 → 删除有限重试（3 次退避）→ Outbox
- **Outbox 原理**：业务数据与待发消息**同一本地事务**提交，`BackgroundService` 扫描投递，解决「DB 成功但消息丢失」双写问题；Outbox 是可靠暂存区，MQ 负责分发，非替代关系
- 无 MQ 版：`Pending → Processing` 认领 + 超时回收 + `FOR UPDATE SKIP LOCKED`；Redis `DEL` 天然幂等
- 框架选型：Hangfire（Dashboard+重试，企业首选，下一步做订单超时取消）/ Quartz.NET（Cron/集群/Misfire）/ Coravel / TickerQ；**Hangfire 不替代 Outbox**

### 13 · 乐观并发 + 幂等性 + 面试路线图（对话 13）

- **xmin 方案**：`uint Version` + `IsRowVersion()` 由 Npgsql 映射到系统列 `xmin`，**无需 migration**；UPDATE 带 `WHERE "xmin"=旧值`，0 行 → `DbUpdateConcurrencyException`
- **双重版本检查**：Service 快速失败 + 保存时捕获兜底时间窗口冲突；Controller 转 409
- **排障**：GET 返回 `version:0`、`createdAt:0001-01-01` → Redis 旧缓存（旧 DTO 无 Version）+ DTO 映射漏赋值，非缺列
- **幂等性（Step 24，仅表设计）**：`Idempotency-Key` 头 + `IdempotencyRecord` 表（Key/RequestHash/ResponseBody）+ Key 唯一索引同事务保证；InMemory 无 xmin 不能测并发
- **高级 .NET 面试六阶段路线图**：ASP.NET Core 进阶 → C# 底层 → 数据库高性能 → 分布式微服务 → 架构设计 → 可观测性；**三级优先级第一级：异步并发（async/await、Task、线程池）、EF Core/SQL 优化、事务隔离级别、缓存一致性、消息幂等、请求管线**
