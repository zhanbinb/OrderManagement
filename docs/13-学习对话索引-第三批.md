## 分阶段摘要

### 14~15 · 阶段 25：C# 异步编程（详见 07 篇）

- async/await 非多线程（状态机）；WhenAll 并发取最慢（实测 4001ms）、一失败其余继续；WhenAny 需配 CTS
- 线程模型：Thread/ThreadPool/Task.Run 三层关系；无 goroutine 等价物；ThreadPool Starvation（`.Result` 阻塞）
- CancellationToken 协作式：`CreateLinkedTokenSource`、`CancelAfter`、失败联动 `cts.Cancel()`
- 竞态实测 10 万次丢 ~24% → lock / `Interlocked` / `SemaphoreSlim(3,3)` + `finally Release()`
- 产出：AsyncDemoController 十余个实验接口 + 5 道面试题全对

### 16 · 阶段 26：请求管线（详见 12 篇）

- 洋葱模型（`next()` 后逆序、短路）；Use/Run/Map；Scoped 依赖须注入 `InvokeAsync` 参数
- 五种 Filter（Authorization/Resource/Action/Exception/Result）；`[ServiceFilter]` 需 DI、`[TypeFilter]` 自动激活；全局 `options.Filters.Add<T>()`
- **异常以 Middleware 为主、Filter 为辅**；产出 `RequestTimingMiddleware`、`ActionLogFilter`、`GlobalExceptionFilter`
- 分工口诀：Middleware 管请求、Filter 管 MVC、业务归 Service

### 17 · 阶段 27.1~27.3：数据库进阶（详见 12 篇）

- PG 默认 Read Committed（每语句新快照，实测 B 提交后读 800）；RR 实测两次读 1000 防幻读；Serializable 需重试
- 单次 SaveChanges 自带事务；多步骤 `BeginTransactionAsync`；**事务内禁 HTTP**
- 防超卖三方案：原子 UPDATE（首选）/ `FOR UPDATE` 悲观 / version 乐观；死锁 = 统一加锁顺序 + `40P01` 重试
- EXPLAIN 实测 Seq Scan+Sort → 建 `idx_orders_created_at`；索引失效（`LOWER()`/`LIKE '%x'`）→ 表达式索引
- 深分页 OFFSET → **Keyset**；覆盖索引 INCLUDE、部分索引；B+Tree 聚簇（InnoDB 叶子存行）vs PG 无聚簇

### 18~19 · 阶段 27.4~28 + 幂等（详见 08 篇）

- 连接池五因（DbContext 生命周期≠连接占用）；外部 HTTP 不进事务（查→调→短事务）
- RabbitMQ vs Kafka 选型；五概念 + 四 Exchange；Docker 部署修 `rabbitmq_data` 卷声明坑
- Producer/Consumer 全链路跑通；手动 ACK、事务 Commit 后才 Ack（At-least-once）
- **幂等落地**：`IServiceScopeFactory` 每消息建 Scope + `ProcessedMessages` 唯一索引 + `ON CONFLICT DO NOTHING` 同事务按影响行数判重 —— 实测第二次 `Duplicate message detected`
- 阶段 29 开篇：幂等三要素 / CAP（P 下权衡非三选二）/ BASE / 2PC-TCC-Saga

### 20 · 阶段 29~30 前半：分布式与架构（详见 09 篇）

- Saga 补偿 = 幂等**增量**新操作（`+2` 而非覆盖）+ 流水表 + `UNIQUE(OrderId, Action)` 同事务；自动为主人工兜底
- Outbox 同事务写 Pending → 后台扫描发布；只保证可靠发布，消费端幂等配套
- 容错四件套（Timeout/Retry 指数退避+Jitter/CircuitBreaker/Fallback）→ `AddStandardResilienceHandler()`
- 微服务按业务边界拆；Gateway 选 YARP/Ocelot；SOLID DIP + Keyed DI 策略；四模式口诀（工厂/策略/模板/装饰器）
- 三层 / Clean（DIP）/ CQRS（≠Event Sourcing）；责任链=Middleware；代理 vs 装饰器

### 21~22 · 阶段 30：DDD 实战（详见 10 篇）

- 四项目拆分（Api→App→Domain←Infra）；NU1202 = Npgsql 版本与 TFM 不匹配
- `Money` record 值对象；聚合根 `EnsurePending` 守卫 + 集合只读暴露；CS0111 构造函数冲突
- EF `OwnsMany`/`OwnsOne` 展开 Money 两列 + 级联删除；独立库 `DddConnection`；迁移命令要点
- 四链路跑通；聚合加载三原则（Include/Select 投影/ExecuteUpdate）；`GetByIdWithoutItems` 不会误删
- DI 排错（IOrderRepository 未注册）；`BusinessException→409` 等 switch 映射；领域事件 SaveChanges→Dispatch→Clear；6 个领域单测

### 23 · DDD 收尾 + 阶段 31 开篇（详见 10/11 篇）

- 乐观并发 `IsConcurrencyToken`（版本进 UPDATE WHERE，0 行 → 409）；聚合=事务边界，跨聚合用事件+Saga+Outbox
- 可观测性三支柱；四类故障（CPU 高/内存泄漏/接口慢 N+1/**饥饿队列涨 CPU 低**）
- 性能优化顺序：定位 → SQL/索引 → EF → 缓存 → 阻塞 → 分配
- 实操 `dotnet-counters monitor`（PID 62725，解读 cpu/heap/threadpool 指标）；生产按需采集 vs 常驻监控
